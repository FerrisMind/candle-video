# candle-video Dependency Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Update `candle-video` direct dependencies to current stable releases, regenerate dependency resolution, and restore a successful build with minimal compatibility fixes.

**Architecture:** The work is split into three phases: update direct dependency constraints in `Cargo.toml`, resolve and inspect breakages through Cargo, then apply narrow source compatibility fixes caused by the new dependency APIs. Verification happens after each phase to separate manifest issues from code issues.

**Tech Stack:** Rust, Cargo, crates.io dependency resolution, `cargo check`, `cargo test --no-run`

---

### Task 1: Update manifest versions

**Files:**
- Modify: `Cargo.toml`

- [ ] **Step 1: Inspect current direct dependencies**

Read `Cargo.toml` and list all entries under `[dependencies]` and `[dev-dependencies]`, including grouped Candle crates:

```toml
[dependencies]
candle-core = { version = "0.9.2", features = ["cuda", "cudnn"] }
candle-nn = "0.9.2"
candle-transformers = "0.9.2"
candle-flash-attn = { version = "0.9.2", optional = true }
tokenizers = "0.22"
hf-hub = "0.4"
clap = { version = "4.0", features = ["derive"] }

[dev-dependencies]
criterion = { version = "0.8", features = ["html_reports"] }
tempfile = "3.0"
bytemuck = "1.0"
proptest = "1.5"
```

- [ ] **Step 2: Determine latest stable releases for each direct dependency**

Use Cargo or crates.io-backed tooling to identify the latest stable versions for each direct dependency before editing `Cargo.toml`. Record the chosen versions so the Candle family stays synchronized.

Run:

```bash
cargo search candle-core --limit 1
cargo search candle-nn --limit 1
cargo search candle-transformers --limit 1
cargo search candle-flash-attn --limit 1
```

Expected: latest stable versions are printed for each crate and can be aligned.

- [ ] **Step 3: Edit `Cargo.toml` in one pass**

Update all direct dependency and dev-dependency version constraints to the latest chosen stable releases while preserving existing feature flags:

```toml
[dependencies]
candle-core = { version = "<latest>", features = ["cuda", "cudnn"] }
candle-nn = "<latest>"
candle-transformers = "<latest>"
candle-flash-attn = { version = "<latest>", optional = true }
tokenizers = "<latest>"
hf-hub = "<latest>"
clap = { version = "<latest>", features = ["derive"] }
```

- [ ] **Step 4: Verify the manifest parses**

Run:

```bash
cargo metadata --no-deps
```

Expected: Cargo prints metadata successfully with no TOML parse errors.

### Task 2: Refresh lock resolution and capture breakages

**Files:**
- Modify: `Cargo.toml`
- Create/Modify: `Cargo.lock` (if generated by Cargo)

- [ ] **Step 1: Generate or refresh dependency resolution**

Run:

```bash
cargo update
```

Expected: Cargo refreshes transitive dependency resolution based on the updated direct constraints.

- [ ] **Step 2: Run a compile-only verification pass**

Run:

```bash
cargo check
```

Expected: either a successful check, or compiler errors that identify exact API breakages introduced by the dependency upgrade.

- [ ] **Step 3: Classify failures before editing code**

Sort errors into:

```text
1. version-resolution problems
2. renamed or removed APIs
3. changed trait bounds or feature flags
4. test/example-only failures
```

Expected: a short failure map that guides minimal compatibility fixes instead of broad refactoring.

### Task 3: Apply compatibility fixes

**Files:**
- Modify: exact Rust source files reported by `cargo check`
- Modify: `Cargo.toml` if a feature flag or crate selection must be adjusted

- [ ] **Step 1: Fix one compiler error cluster at a time**

Use the exact compiler diagnostics to patch only the affected APIs. Typical examples:

```rust
// before
let value = some_api(old_arg)?;

// after
let value = some_api(new_arg)?;
```

or

```rust
// before
use hf_hub::api::sync::Api;

// after
use hf_hub::api::sync::Api;
// keep import if still valid, otherwise replace with the new module path reported by the crate docs/compiler
```

- [ ] **Step 2: Re-run compile verification after each fix batch**

Run:

```bash
cargo check
```

Expected: the current batch of errors is gone; remaining errors are narrower than before.

- [ ] **Step 3: Adjust tests/examples only if the upgraded APIs require it**

When breakages are isolated to tests or examples, patch those call sites directly instead of reshaping library code unnecessarily.

```rust
// example shape only; use the exact updated API once the compiler points to it
let cli = Args::parse();
```

### Task 4: Final verification

**Files:**
- Modify: any remaining files needed for compatibility

- [ ] **Step 1: Run final build verification**

Run:

```bash
cargo check
```

Expected: PASS

- [ ] **Step 2: Run test compilation verification**

Run:

```bash
cargo test --no-run
```

Expected: PASS, or a smaller set of remaining example/test-only failures to fix immediately.

- [ ] **Step 3: If `cargo test --no-run` fails, fix the reported test/example breakages**

Use the exact compiler output to patch the remaining call sites and rerun:

```bash
cargo test --no-run
```

Expected: PASS
